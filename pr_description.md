## Overview / Context
This PR introduces an automated, resilient resume synchronization and extraction pipeline. Instead of manually maintaining duplicate employment records across code components and PDF files, users can now upload or replace `Resume.pdf` in a dedicated public object storage (Supabase Storage). 

A scheduled and on-demand GitHub Action pipeline automatically downloads the PDF, compares its cryptographic SHA-256 checksum to prevent redundant API consumption, extracts structured professional experience using Google's **Gemini 3.8 Flash** with strict JSON Schema constraints, and dynamically updates the Experience timeline and Schema.org JSON-LD structured data on the homepage.

To eliminate local Git desync and accidental production overwrites, updates generated by the pipeline are delivered via automated Pull Requests with markdown diff summaries.

---

## Proposed Changes

### 1. Data Decoupling & Types
- **`types/experience.ts`**: Introduced strong TypeScript definitions (`ExperienceItem`, `AlumniItem`, `ExperienceData`) defining the schema for the timeline UI and Schema.org `Person` JSON-LD data.
- **`data/experience.json`**: Decoupled hardcoded employment data and SEO metadata from the React component into a centralized JSON source of truth.
- **`data/resume-hash.txt`**: Added persistent SHA-256 hash tracking to prevent unnecessary LLM invocations.

### 2. Core Synchronization & AI Extraction Engine
- **`scripts/sync-resume.mjs`**:
  - Implemented automatic download from `SUPABASE_RESUME_URL` (with fallback to local `public/Resume.pdf`).
  - Integrated a **SHA-256 Hash Guard** for early-exit (0ms wasted quota if PDF has not changed).
  - Integrated **Gemini 3.8 Flash** multimodal extraction using native buffer processing and strict JSON response schemas.
  - Built-in multi-stage runtime validation verifying mandatory fields (`company`, `role`, `period`, `description`, `alumniOf`) to safeguard against malformed data.
- **`package.json`**: Added `"sync:resume": "node scripts/sync-resume.mjs"` script for local testing and CLI updates.

### 3. Dynamic Presentation
- **`app/components/Experience.tsx`**: Refactored the component to dynamically render work experience and inject SEO structured data from `data/experience.json`, preserving full responsiveness and animations.

### 4. CI/CD & Automated PR Workflow
- **`.github/workflows/sync-resume.yml`**: Configured a GitHub Actions workflow triggered weekly via Cron or on-demand via `workflow_dispatch`. Changes are submitted through automated Pull Requests using `peter-evans/create-pull-request@v6` to maintain clean git history and prevent branch conflicts.
